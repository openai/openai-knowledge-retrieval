# 1. Quick Reference (TL;DR)
- What: NFG’s standardized IT Infrastructure & Security posture, hosting options, connectivity, logging, and DR/BCP commitments to support client trust and deal execution.
- Who to engage: Infra Services (Alex Chen), Security Assurance (Priya Nair), Privacy (Legal-Privacy), Deal Desk (Sales Ops), DPO (EU deals).
- SLAs:
  - Core platform uptime: 99.95% monthly; VPN/SFTP: 99.90%.
  - Incident response: Sev-1 triage within 15 minutes; client comms within 60 minutes (NFG-IR-0003).
  - Support: 24x7 for Sev-1/2; business hours for Sev-3/4.
- DR/BCP:
  - Tier 1 RPO 15 min / RTO 2 hours; Tier 2 RPO 1 hour / RTO 8 hours; Tier 3 RPO 24 hours / RTO 48 hours.
- Data residency: US/EU/CA hosting options; client-selectable where contractually required.
- Encryption: Data at rest AES-256; in transit TLS 1.2+; KMS-backed keys with dual control (NFG-CRY-0201).
- Do:
  - Use the approved talk track for SOC2/ISO certifications.
  - Capture security requirements in SFDC fields (see Section 8).
  - Route exceptions via Deal Desk → Security Assurance in SNOW (SEC-EXC).
- Don’t:
  - Commit to custom controls or data residency not listed in Section 14 without approvals.
  - Share architecture diagrams externally without CISO review (NFG-SEC-INFOCLASS).

# 2. Customer Personas and Use Cases
- Asset Managers (Buy-Side): Require audited controls, SFTP for trade files, EU data residency for UCITS funds.
- Banks/Prime Brokers: Require VPN+IP allowlist, message integrity checks, near-real-time logging export.
- Insurers: Need Tier 1 DR for daily valuations; request annual pen test attestation and DPA.
- FinTech Platforms: Prefer API-first, webhook alerts, sandbox segregation, and SOC2 report access.

Fit:
- Customers needing managed secure file exchange, resilient hosting, and standard regulatory attestations.
- Deals requiring clear SLAs, DR tiers, and security questionnaires with rapid turnaround.

Non-fit (refer to Custom Solutions team):
- On-prem deployment, proprietary HSM requirements, or client-owned cloud tenancy management.
- Sub-24-hour bespoke pen test cycles or client-supplied endpoint agents on NFG infrastructure.

# 3. Qualification and Discovery Questions
- Business impact/tier:
  - What is the maximum tolerable downtime (hours)? Data loss tolerance (minutes)?
- Data sensitivity:
  - Will we process PII/PCI/PHI? Which data elements? Any special categories (GDPR Art. 9)?
- Residency and sovereignty:
  - Must data be stored/processed in US/EU/CA only? Any cross-border transfer constraints?
- Connectivity:
  - Do you require SFTP or site-to-site IPsec? Static source IPs? Certificate pinning?
- Logging and audit:
  - Do you need near-real-time log export? Which SIEM? Required retention period?
- Compliance:
  - Which artifacts are required (SOC2 Type II, ISO-27001 SoA, SIG/CAIQ)?
- Red flags:
  - Requests for custom crypto, client-managed keys in NFG tenancy, unrestricted admin access, or changing our incident severity definitions.

# 4. Product/Policy Overview
Capabilities:
- Hosting: Multi-region (AWS us-east-1/us-west-2, Azure westeurope, Canada Central) with active-active for Tier 1.
- Network: Zero Trust access via Zscaler; optional IPsec VPN, SFTP with SSH key-only auth, IP allowlisting.
- Identity: Okta SSO, SCIM provisioning; MFA enforced; least privilege via RBAC (NFG-IDM-1002).
- Data Protection: AES-256 at rest, TLS 1.2+ in transit, secrets in Vault, daily backups with cross-region replication.
- Logging: Centralized Splunk; optional client log export via S3 signed URLs or syslog TLS (LOG-EXPT).
- DR/BCP: Tested semi-annually; documented in NFG-BCP-0004 with evidence in Archer.
- Security Assurance: Annual SOC2 Type II, ISO-27001 certified, annual CREST pen test, vulnerability management (NFG-VM-1203).

Limitations:
- No on-prem installations; no co-location access.
- No client-installed EDR/agents on NFG-managed hosts.
- Custom cryptography, customer-controlled KMS in NFG tenancy, or sub-hour DR RTO not supported without exec approval.

Dependencies:
- Internet connectivity, client firewall rules for VPN/SFTP, accurate IP/cert exchange, validated DPA where personal data is involved.

# 6. Deal Desk Workflow
Steps:
1) Capture Requirements (Owner: AE)
   - Complete SFDC Security Requirements fields (Section 8).
   - Attach client questionnaire (SIG/CAIQ) and DPA draft if applicable.
   - SLA/DR tier selected; note data residency and connectivity needs.

2) Initial Review (Owner: Deal Desk, SLA: 1 business day)
   - Validate margin threshold and discount guardrails.
   - Create SNOW request SEC-REQ with artifacts.

3) Security Assurance Assessment (Owner: Sec Assurance, SLA: 3 business days)
   - Map client asks to NFG controls; identify gaps.
   - If exception needed, create SEC-EXC; propose compensating controls.

4) Technical Feasibility (Owner: Infra Services, SLA: 2 business days)
   - Validate VPN/SFTP parameters, log export capacity, DR tier feasibility.

5) Legal & Privacy (Owner: Legal-Privacy, SLA: 3 business days)
   - Finalize DPA, SCCs/IDTA if cross-border; review residency commitments.

6) Approval & Term Sheet (Owner: AE + Deal Desk, SLA: 1 business day)
   - Apply approval matrix; generate mini term sheet (Section 12).

7) Close/Provision (Owner: Customer Onboarding, SLA: 5 business days)
   - Create SNOW change for provisioning; confirm secrets exchange; schedule DR enrollment.

Escalation Path:
- Missed SLA or Sev-1 client demand: escalate in order — Deal Desk Lead → Deputy CISO → Head of Infra → CRO.

# 10. Procedures
Onboarding — Connectivity and Security Controls
1) Intake (AE)
   - Ensure SFDC security fields completed; attach CAIQ/SIG and DPA draft.
   - Control check: Deal Desk verifies completeness; evidence: SFDC validation logs.

2) Technical Design (Infra)
   - Confirm VPN/SFTP parameters; exchange IPs and SSH keys via Vault SecureShare.
   - Control check: Dual control for key activation (NFG-CRY-0201); evidence: SNOW change CHG-2025-10-0007.

3) Provisioning (Infra)
   - Create tenant (ITINF-CORE), apply baseline security (CIS hardened AMIs, RBAC).
   - Set DR tier and replication policies.
   - Control check: Segregation of duties enforced; evidence: SNOW tasks and Terraform plan outputs.

4) Legal Finalization (Legal-Privacy)
   - Execute DPA, SCCs/IDTA if needed; archive in Archer.
   - Control check: DPO sign-off for EU data; evidence: Archer record PRIV-2025-EU-114.

5) Client Validation (Support)
   - Perform connectivity test (VPN failover, SFTP transfer), share status API endpoint.
   - Control check: Evidence in SNOW test log; client UAT sign-off captured.

Servicing — Incident Communications
1) Detect (SOC)
   - Alerts via Splunk/CloudWatch; Sev assignment per NFG-IR-0003.

2) Notify (Support)
   - For Sev-1/2, send initial comms within 60 minutes using template COMM-IR-01; include status page link.

3) Mitigate (Infra + App teams)
   - Execute runbooks; if DR failover needed, invoke per NFG-BCP-0004.

4) Post-incident (Security Assurance)
   - RCA within 5 business days; corrective actions tracked in SNOW PRB.

Exceptions — Security Control Exception
1) Submit SEC-EXC (AE via Deal Desk)
   - Describe requested deviation (e.g., client requires TLS 1.3 only).

2) Assess (Security Assurance)
   - Evaluate risk, propose compensating control (e.g., TLS 1.2 disabled in client VNet only).

3) Approve (CISO/Legal if privacy impact)
   - Capture approval in SNOW; update term sheet with binding commitments.

4) Implement (Infra)
   - Execute change; regression testing; evidence attached to SEC-EXC.

# 11. Objection Handling Matrix
- “Do you support on-prem?”
  - Response: We operate a secure, audited cloud model with 99.95% uptime and Tier 1/2 DR options. On-prem is not offered; we meet on-prem control outcomes via dedicated VPC/VNet and private link (SEC-ENH).
- “We need EU-only data storage.”
  - Response: We provide EU residency with processing and storage confined to Azure West Europe; cross-border blocked unless SCC/IDTA executed. See Section 14.
- “Can we manage encryption keys?”
  - Response: We use provider KMS with dual control and key rotation. Customer-managed keys in our tenancy are not supported; we can enforce per-tenant keys and provide audit logs.
- “Share pen test results.”
  - Response: We provide third-party attestation letters and executive summaries under NDA (PEN-ATTST). Full reports contain sensitive details and are not distributed.
- “We need raw logs in our SIEM.”
  - Response: LOG-EXPT streams via TLS syslog or S3 signed URLs with 1-minute latency. Overage fees apply beyond 100 GB/day.

# 14. Regional Variations
- EU/UK:
  - Data residency options in Azure West Europe; SCCs/IDTA required for cross-border support/processing.
  - DPIA may be required for special category data (GDPR Art. 35); DPO sign-off mandatory.

- Canada:
  - PIPEDA and provincial laws (e.g., Quebec Law 25) may require local storage; Canada Central region available.

- US:
  - NYDFS-500 for covered entities; enhanced logging retention (7 years for audit artifacts under NFG-SEC-17a-4-Archival).

- APAC:
  - MAS-TRM-aligned controls documented; no local residency regions offered; use standard cross-border mechanisms and client consent.

Note: Where regional commitments conflict, the stricter standard applies. See also: NFG-DATA-0009 (Data Residency and Sovereignty).
